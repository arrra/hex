# Mirofish Audience Simulation

Mirofish simulates how audiences react to content/campaigns using multi-agent AI. Use it to vibe-check content before publishing.

## Infrastructure

- **Host:** GCE VM `mirofish` in `mrap-dev` (us-east1-b, e2-small)
- **Access:** Tailscale `100.108.180.3` / hostname `mirofish`
- **Frontend:** `http://mirofish:3000`
- **Backend API:** `http://mirofish:5001/api`
- **LLM:** OpenRouter (Gemma 3 27B main, 12B boost)
- **Deploy:** `hex mirofish deploy`
- **Status:** `hex mirofish status`

## API Flow (5 steps)

### Step 1: Create project + generate ontology
```
POST http://mirofish:5001/api/ontology/generate
Content-Type: multipart/form-data

files: <seed document(s) — PDF/MD/TXT>
simulation_requirement: "Predict how AI practitioners and tech workers react to these social media posts"
project_name: "Campaign: Tech Dictionary"
additional_context: "Target audience: software engineers, founders, AI builders on X/Twitter and LinkedIn"
```
Returns: `project_id`, `ontology` (entity types, relationship types)

### Step 2: Build knowledge graph
```
POST http://mirofish:5001/api/build
{"project_id": "<from step 1>"}
```
Returns: `task_id` (async — graph building runs in background)

### Step 3: Poll task status
```
GET http://mirofish:5001/api/task/<task_id>
```
Returns: status (processing/completed/failed), progress (0-100), result

### Step 4: Run simulation
Use the frontend at `http://mirofish:3000` to configure and run the simulation, OR use the simulation API endpoints (see `backend/app/api/simulation.py` for full route list).

Key simulation config:
- **Agent count:** 50-200 (more = better signal, higher cost)
- **Rounds:** 20-40 (each round = one "day" of simulated social activity)
- **Platforms:** Twitter-style (short-form viral) + Reddit-style (threaded debate)

### Step 5: Fetch report
Reports are generated by the ReportAgent after simulation completes. Access via frontend or report API.

## Seed Document Format

For content testing, create a seed document like:
```markdown
# Campaign: [Name]

## Context
[Who is the author, what's their brand, what platforms]

## Target Audience
[Describe the audience segments to simulate]

## Posts to Test

### Post 1
[Full post text]

### Post 2
[Full post text]

## Prediction Requirements
- Which posts generate the most engagement?
- Which audience segments respond positively vs negatively?
- What counter-narratives or pushback emerge?
- Which posts are most likely to go viral?
```

## Workflow for hex

1. Pull liked posts from `projects/brand/proposals/reactions.json`
2. Bundle into a seed document (MD file)
3. Upload via ontology/generate endpoint
4. Build graph
5. Run simulation (50 agents, 30 rounds for quick test; 200 agents for production)
6. Fetch report, extract signals
7. Present results to Mike

## Cost per simulation
- 50 agents, 20 rounds: ~$0.50-1.00 (OpenRouter)
- 200 agents, 30 rounds: ~$2-4.00
- LLM calls are the only cost; VM is ~$13/mo fixed

## Project management
```
GET  /api/project/list          — list all projects
GET  /api/project/<id>          — project detail
DELETE /api/project/<id>        — delete project
POST /api/project/<id>/reset    — reset to re-run
```

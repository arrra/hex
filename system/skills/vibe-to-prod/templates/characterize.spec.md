**Mode:** execute

## Context

Generate characterization tests that lock down the current behavior of target modules
before any refactoring. This is Phase 2 of the vibe-to-production pipeline.

**Principle:** Never refactor without characterization tests. AI excels at generating
these because they require observation, not understanding.

**Target:** `{{PROJECT_PATH}}`
**Output:** `{{PROJECT_PATH}}/tests/characterization/`
**Modules:** `{{MODULE_LIST}}`

`{{MODULE_LIST}}` is a comma-separated list of absolute paths to Python modules.

**CRITICAL: Do NOT modify any source module under test.**

### t-2: Generate characterization tests for each module
PENDING

**Spec:** For each module path in `{{MODULE_LIST}}` (split on commas, strip whitespace),
generate inline-snapshot characterization tests using the following approach:

For each module in the list:
1. Read the module source to identify all public functions and classes (those not starting with `_`)
2. For each public function/method, generate test cases covering:
   - Typical/happy-path inputs
   - Boundary values: empty strings, empty lists, `None`, zero, negative numbers, large inputs, unicode
   - Expected exception types for invalid inputs (use `pytest.raises`)
3. Use `snapshot()` from `inline_snapshot` for all return value assertions
4. Write tests to `{{PROJECT_PATH}}/tests/characterization/test_<module_stem>.py`
   where `<module_stem>` is the filename without `.py` extension

**Constraint:** Do NOT modify any source module under test. Only write new test files.

**Test file structure to follow:**

```python
"""
Characterization tests for <module_path>.
Generated by vibe-to-prod Phase 2.
DO NOT edit manually — these tests capture existing behavior.
To update after intentional behavior changes:
    pytest tests/characterization/test_<module_stem>.py --inline-snapshot=fix
"""
import pytest
from inline_snapshot import snapshot

# Import the module under test
from <module_import_path> import <functions_and_classes>


def test_<function_name>_typical():
    result = <function_name>(<typical_input>)
    assert result == snapshot()


def test_<function_name>_empty():
    result = <function_name>(<empty_input>)
    assert result == snapshot()


def test_<function_name>_boundary():
    result = <function_name>(<boundary_input>)
    assert result == snapshot()


def test_<function_name>_exception():
    with pytest.raises(<ExceptionType>):
        <function_name>(<invalid_input>)
```

After writing all test files, run pytest with `--inline-snapshot=fix` to auto-populate
the snapshot values from the current (live) behavior:

```bash
mkdir -p "{{PROJECT_PATH}}/tests/characterization"

# Create __init__.py if missing
touch "{{PROJECT_PATH}}/tests/__init__.py" 2>/dev/null || true
touch "{{PROJECT_PATH}}/tests/characterization/__init__.py" 2>/dev/null || true

# Auto-populate snapshots from current behavior
cd "{{PROJECT_PATH}}"
pytest tests/characterization/ --inline-snapshot=fix -v 2>&1 || true
```

**Verify:**
```bash
test -d {{PROJECT_PATH}}/tests/characterization && echo "DIR EXISTS"
ls {{PROJECT_PATH}}/tests/characterization/test_*.py | wc -l
```

### t-3: Verify all characterization tests pass
PENDING

**Spec:** Run all characterization tests (without `--inline-snapshot=fix`) to confirm
the snapshots were correctly populated and all tests pass. This is the baseline that
must be preserved through all subsequent refactoring.

```bash

set -uo pipefail

cd "{{PROJECT_PATH}}"

echo "=== Running characterization tests ==="
```

If tests fail due to missing snapshots, re-run with `--inline-snapshot=fix` then
re-run without it to confirm they pass.

Log the test count and pass rate to `{{OUTPUT_DIR}}/characterization-summary.txt`:
